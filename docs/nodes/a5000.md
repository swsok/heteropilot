# Node profile — the A5000 node

*Read this only after `bash scripts/whichnode.sh` says `detected node : a5000`.*

> **This file is the thinnest of the three, and deliberately so.** It was written
> on 2026-08-28 from committed artifacts, not from the node itself — nobody has
> been on that machine since the project moved. Everything below is either quoted
> from a committed file or marked as unverified. **When you are next on this node,
> run the detector and fill this in from what it reports.**

## What the artifacts record

`profiles/accelerators/a5000.yaml`, `source: measured`, with per-field provenance:

| field | value | provenance |
| --- | --- | --- |
| model | RTX A5000, `sm_86` | — |
| `memory_gb` | 24 | measured (`nvidia-smi` reports 24564 MiB) |
| `memory_bandwidth_gbps` | 768 | **vendor_spec** — NVIDIA's published 384-bit GDDR6 figure, never microbenchmarked |
| `perf_data` | `profiler/perf/A5000/` | measured 2026-08-07, vLLM 0.19.0, CUDA 12.8 |
| power | see the file | measured 2026-08-14, `nvidia-smi power.draw` at 10 Hz, 2,602 samples at util ≥ 90 % during a real 300-request vLLM bench. Raw: `experiments/results/a5000_power/` |

`docs/PROJECT_REPORT.md` records the node as **2 × RTX A5000**. The per-watt
comparison in `docs/HANDOVER_A40.md` §2 uses 694 GB/s achieved and 227.6 W.

## Unverified here

- Device count on the box today, PCIe/NVLink topology, NUMA layout, core and RAM
  counts. None of it is in any committed artifact.
- Whether `.venv` and `.venv-vllm` still exist there, and whether ASTRA-Sim is
  built. Assume not; follow `CLAUDE.md` §Environment.

## Notes that do carry over

- **sm_86, the same architecture as the A40.** The CUDA profiler works unchanged;
  `docs/hardware_roadmap.md` used this to argue the A40 needed no new profiler
  work, and the same reasoning applies in reverse.
- A5000 artifacts are **measurements of this node**. If you are reading this from
  the A40 or NPU node, they are measurements of a machine you are not on: do not
  re-run, extend, or relabel them (absolute rule 3).
- `python -m serving` shells out to a bare `python -m chakra`, so the venv must be
  on `PATH`, not merely invoked by full path:
  `export PYTHONPATH=$PWD && export PATH="$PWD/.venv/bin:$PATH"`.
